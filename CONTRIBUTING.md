# Contributing

Thank you for helping. This page covers the practical steps; the legal side is in [CONTRIBUTOR_TERMS.md](CONTRIBUTOR_TERMS.md).

## Before you start

1. Open an issue for what you want to do ([translator](../../issues/new?template=translator.yml), [voice actor](../../issues/new?template=voice_actor.yml)), so two people do not work on the same thing.
2. Wait for a maintainer to reply. For a new language, the maintainer creates its folder for you.

## Making changes

You do not need to know Git well. Either:

- **In the browser:** open a file on GitHub, click the pencil icon, edit, and choose "Create a new branch and start a pull request".
- **On your computer:** fork the repository, clone it, edit, push to your fork, and open a pull request.

Keep each pull request to one language or one voice role, so it is easy to review.

## Pull request checklist

- [ ] The work is my own, and none of it is AI-generated.
- [ ] I agree to [CONTRIBUTOR_TERMS.md](CONTRIBUTOR_TERMS.md).
- [ ] Translations: I only changed the `translation` and `status` columns.
- [ ] Voice: file names match the role script exactly.

## Review

- Translations are reviewed by a native speaker of that language when one is available. The first experienced translator of a language usually becomes its reviewer.
- A reviewer may ask for changes. Discussions stay in the pull request so everyone can follow them.
- Merged work goes into the game at the next build, not instantly.

## Credits

Tell us in your first pull request how you want to be credited (name or handle, and optionally a link). You can change it later with another pull request to [CREDITS.md](CREDITS.md).
